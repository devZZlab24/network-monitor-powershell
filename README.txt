==========================================================
  монитор сети. Чистый PowerShell, БЕЗ PHP.
==========================================================

СОСТАВ ПАПКИ:
  start_monitor.bat      -запуск мониторинга (двойной клик)
  stop.bat               -остановка
  report.bat             -отчёт по собранным данным
  net_monitor.ps1        -сам монитор
  analyzer.ps1           -анализатор лога
  net_log.csv            -лог (создаётся автоматически)
  config\monitor.ini     -настройки: интервал, цели, пороги, флаги ВКЛ/ВЫКЛ
  config\diagnoses.txt   -тексты диагнозов (можно править под себя)

УСТАНОВКА (2 шага):
  1. Создать папку на раб столе и поестить все файлы в нее.
  2. Двойной клик по start_monitor.bat.

  Если Windows заблокировал скрипт: правый клик по net_monitor.ps1 ->
  Свойства -> кнопка "Разблокировать" -> ОК, и запустите заново.

что монитор выдает:
  Каждые ~2 секунды пишет в net_log.csv строку:
    - DNS: основной (роутер/провайдер) и внешний 8.8.8.8, время ответа
    - TCP: подключение к 1.1.1.1:443 и 8.8.8.8:53 (сам канал)
    - Пинг роутера (шлюза)
    - Состояние сетевого адаптера (не отвалился ли линк)
  В поле Note ставятся флаги:
    INET_FAIL    - интернет пропал полностью
    TCP_SLOW     - интернет живой, но медленный
    GW_FAIL      - роутер не отвечает (проблема в локальной сети)
    DNSL_FAIL    - основной DNS не ответил
    DNSE_FAIL    - внешний DNS не ответил
    DNSL_SLOW    - основной DNS отвечал медленно
    ADAPTER_DOWN - сетевой адаптер терял линк

  Окно можно свернуть; если скрипт упадёт, то bat сам его перезапустит.
  ПК на время замера лучше не усыплять (сон = никогда), иначе в логе будут дыры.

ОТЧЁТ в (report.bat):
  - диагноз по флагам с готовыми советами ("смотри роутер", "смотреть
    провайдера", "сменть DNS" и т. д.) -тексты берутся из файла diagnoses.txt
  - уточнение: виноват провайдер или локальная сеть (сравнивается пинг
    роутера в моменты сбоев)
  - список всех периодов полного пропадания с длительностью
  - топ худших моментов DNS
  - ваши отметки MARK и что сработало рядом с ними
  - средние показатели, почасовая разбивка, события Windows о сети

ПОРЯДОК РАБОТЫ:
  1. start_monitor.bat -> живёт 2 дня (окно свернуть).
  2. При каждом зависании -файл MARK в папке.
  3. Через 2 дня: stop.bat, затем report.bat.
  4. По отчёту видно, кто виноват: DNS, Wi-Fi/роутер/коммутатор или провайдер.
